# Brandon's MCP release overview

**Goal:** make the local, open-source MCP installable and useful for an assistant that animates a character and exports it. Release the local MCP first; hosted transport and ChatGPT integration are later stages. The animation-agent prototype and its installed skills are separate.

## What is ready for review

[Draft PR #13](https://github.com/Uthana/uthana-mcp/pull/13) adds Linux/macOS CI, a fresh-wheel protocol check, a packaged read-only smoke command, and `X-Uthana-AppId: mcp` plus a versioned User-Agent on requests to Uthana. It also adds a [first-result walkthrough](FIRST-RESULT.md), [operational notes](OPERATIONS.md), and Uthana-owned [Tar GLB/FBX source files](examples/tar/README.md). The GLB is rigged and self-contained; uploading it should exercise the same path a customer uses for their character. The existing Tar character ID is an optional shortcut, not the expected result of an upload.

At commit `d025b13`, 368 offline tests, lint, formatting, and source/wheel builds passed. The wheel installed outside the checkout and passed a credential-free protocol smoke test. All four CI jobs passed on Ubuntu and macOS with Python 3.11 and 3.12. The Tar files were structurally inspected and their hashes checked in the source archive. A read-only production catalog call confirmed the existing Tar ID. **No paid generation or live upload → animation → export acceptance run has been performed.**

## Your release decisions and checks

1. **Choose the first-release scope.** PR #13 is the local MCP readiness layer. [Rigging #6](https://github.com/Uthana/uthana-mcp/pull/6), [V1 adapter #7](https://github.com/Uthana/uthana-mcp/pull/7), [automatic stitching #10](https://github.com/Uthana/uthana-mcp/pull/10), [Windows #11](https://github.com/Uthana/uthana-mcp/pull/11), and [text-to-character #12](https://github.com/Uthana/uthana-mcp/pull/12) can be reviewed on their own merits. #12 depends on #11; #10 requires its backend and client releases. [Planning #9](https://github.com/Uthana/uthana-mcp/pull/9) concerns later hosted and ChatGPT stages. The [detailed handoff](RELEASE-REVIEW.md) explains merge order and overlap.
2. **Review public disclosure before changing repository visibility.** A removed staging acceptance report remains reachable in Git history and contains internal identifiers and account observations. [The audit notes](RELEASE-REVIEW.md#public-release-audit) identify the commit. Decide whether that history is acceptable or whether the public repository needs a clean history. Confirm the intended distribution terms for the Tar 3D files as well.
3. **Run one real first-result acceptance.** Use [Tar's GLB](examples/tar/cXi2eAP19XwQ.glb) and the [walkthrough](FIRST-RESULT.md): clean install, account access, rigged upload, cost estimate, one generated motion, preview, export, then import/playback in the chosen game engine. Record the selected commit, OS/client, request/job/motion IDs, actual charge, output file, and any quality issue. Do not call that workflow proven before this run. Unreal playback remains unverified.
4. **Connect operational checks to the deployment you choose.** Run `uthana-mcp-smoke` for local/package health. `--api-read` optionally verifies configured credentials without creating assets or jobs. The API app header makes MCP-originated requests visible in existing backend logs, though it cannot count local discovery calls. For a hosted MCP, decide separately how its HTTP health, error monitoring, and authentication use existing infrastructure; [operational notes](OPERATIONS.md) give the boundary.

After selecting feature PRs, rerun the complete CI and fresh-wheel check on the integrated branch. Review the resulting setup text and tool list for conflicts. Keep any live spending within the agreed validation budget and report paid request IDs separately.
